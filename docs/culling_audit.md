## 3. Correctness & Robustness Findings

| ID | Severity | Finding | Location | Effect | Fix |
|---|---|---|---|---|---|
| **C1** | **Bug** | **Unfreezing the culling camera does not invalidate occlusion history (and scene changes while frozen leave a stale pyramid).** When `settings.isCameraFrozen` switches `true → false`, `hiz.hasContent()` is still `true` (holding the freeze-frame pyramid), `camera.isCut()` is `false` after WASD fly-out, and `isLayoutChanged` is `false`. `occlusionHistory()` returns `Valid`, so the first unfrozen frame's early phase projects `camera.prevViewProj` (where the flying camera was last frame) against the old freeze-frame pyramid. Separately, if a model is loaded/unloaded while frozen (`isLayoutChanged && isPyramidFrozenThisFrame`), `isFreezeStart` stays `false`, so `hiz.recordBuild` skips rebuilding the pyramid on the `SceneChanged` frame and the next frame reports `Valid` against the pre-edit pyramid | [vk_meshlet_culling.cpp:127-134](../src/render/vk_meshlet_culling.cpp#L127-L134), [:361-378](../src/render/vk_meshlet_culling.cpp#L361-L378), [:437-439](../src/render/vk_meshlet_culling.cpp#L437-L439) | On unfreeze, early occlusion tests unrelated depth (massive false early rejects and late recovery spike for 1 frame, wrong phase-debug output). On scene edit while frozen, subsequent frozen frames test new geometry against the pre-edit pyramid | Track `const bool isUnfreeze = wasCameraFrozen && !settings.isCameraFrozen;` and invalidate history on unfreeze (e.g. `NoPyramid` or a dedicated `CameraUnfrozen` enum value). Include `isLayoutChangedThisFrame` in `isFreezeStart` (or drop freeze on layout change) so the pyramid refreshes for the new scene |
| **C2** | **Bug** | **Normal-cone test can falsely cull front-facing meshlets when `coneCutoff == 127`.** `meshopt_computeMeshletBounds` clamps `cone_cutoff_s8` to `127` (`1.0`) when `cone_cutoff + e0 + e1 + e2 > 1.0`, while retaining a non-zero quantized `cone_axis_s8` ([meshletutils.cpp:259-271](../ThirdParty/_deps/src/meshoptimizer/src/meshletutils.cpp#L259-L271)). Because `snorm8` rounding can give `length(coneAxis / 127.0) > 1.0` (e.g., `(70, 75, 76) / 127` has length `1.00532`, so `dot(u, axis) > 1.0` inside a `5.90°` cone around `axis`), a meshlet with `mindp = 0.1001` (`84.25°` half-angle) exceeds `90°` (`84.25° + 5.90° = 90.15°`). Beyond `~188 × radius`, `dot(offset, axis) >= 1.0 * length(offset) + radius` evaluates `true` for a front-facing triangle, contradicting `types.hpp:43` (`cutoff 127 never culls`) | [meshlet_cull.slang:29-35](../shaders/passes/meshlet_cull.slang#L29-L35), [geometry_store.cpp:343-355](../src/core/geometry_store.cpp#L343-L355), [types.hpp:43-45](../src/core/types.hpp#L43-L45) | Rare distant false-culling of wide-cone (`mindp` just above `0.1`) single-sided meshlets | Short-circuit `if (meshlet.coneCutoff == 127) return false;` in `isConeBackfacing`, and/or zero `coneAxis` in `geometry_store.cpp` whenever `bounds.cone_cutoff_s8 == 127` |
| **C3** | **Bug (latent)** | **`EntityFlag::Active` is out of sync between `MeshletCulling` templates and `FrameData::writeNodeInstances`.** `buildTemplates()` skips entities without `EntityFlag::Active`, but only rebuilds when `frameData.layoutGeneration()` changes (model load/unload/instantiate). `FrameData::writeNodeInstances()` skips writing `GpuNodeInstance` rows for inactive entities every frame without bumping `layoutGeneration()`, even though `vk_frame_data.cpp:122` explicitly anticipates toggling `Active` (`reactivation must not jump by the whole pause's motion`) | [vk_meshlet_culling.cpp:121-124](../src/render/vk_meshlet_culling.cpp#L121-L124), [:235](../src/render/vk_meshlet_culling.cpp#L235), [vk_frame_data.cpp:121-125](../src/core/vk_frame_data.cpp#L121-L125), [:178](../src/core/vk_frame_data.cpp#L178) | Benign while nothing clears `Active` at runtime. Once any system deactivates an entity, `cullInstances` reads stale or uninitialized `GpuNodeInstance` rows (ghost geometry, or out-of-bounds BDA fault on a freshly grown buffer). Same gap in `RayTracingScene::buildTemplates` | Either bump `layoutGeneration` whenever `EntityFlag::Active` changes, or store an active flag in `GpuNodeInstance::flags` and always write valid rows so `cullInstances` skips inactive instances on the GPU |
| **C4** | **Bug (latent)** | **DGC `ensureFrameCapacity` clamps multi-phase buffer capacity to `maxIndirectSequenceCount` and can throw.** `meshletsPerSequence()` floors `perSequence` at `divideRoundUp(totalMeshlets, maxIndirectSequenceCount)` (for 1 phase), whereas `dgc.prepareFrame()` requests `phaseSequences * kCullPhaseCount` (2 phases + per-bin ceil). `ensureFrameCapacity()` then clamps `newCapacity` to `props.maxIndirectSequenceCount` and throws if `newCapacity < minSequences`. Additionally, `while (newCapacity < minSequences) newCapacity *= 2;` does not check `minSequences` before doubling (32-bit wrap risk if `minSequences > 2^31`) | [vk_meshlet_culling.cpp:355-357](../src/render/vk_meshlet_culling.cpp#L355-L357), [vk_dgc.cpp:153-176](../src/render/vk_dgc.cpp#L153-L176) | Throws `std::runtime_error` if `totalMeshlets > maxIndirectSequenceCount / 2` with a small UI `maxMeshletsPerSequence` setting (e.g. `1`) | Enforce `binMaxSequences[bin] <= props.maxIndirectSequenceCount` per execute (what Vulkan requires), not on the combined multi-phase buffer capacity; use `std::bit_ceil` or pre-validate before doubling |
| **C5** | **Robustness** | **`worldToObject` divides by zero on singular instance transforms.** `dot(c0, r0)` is `det(mat3(world))`. A transform with one zero scale axis (e.g. `(1, 1, 0)`, which flattens a mesh onto a plane while keeping XY-parallel triangles non-degenerate and visible) produces `±inf`/`NaN` in `objectCamera` | [meshlet_cull.slang:10-18](../shaders/passes/meshlet_cull.slang#L10-L18), [:254-257](../shaders/passes/meshlet_cull.slang#L254-L257) | Spurious cone-culling of singularly-scaled meshes when `inf` signs align in `dot(offset, axis) >= cutoff * length(offset) + radius` | Compute `det = dot(c0, r0)` once per group; skip cone culling when `abs(det) <= 1e-20` |
| **C6** | **Edge case (spec trade-off)** | **Unjittered frustum and late Hi-Z vs jittered rasterization (±0.5 render px).** Per [engine_spec.md §12.2](./engine_spec.md#122-jitter-and-resolution), `cullViewProj` and `occlusionViewProj` are unjittered while `mesh_raster` applies Halton(2,3) ±0.5 px jitter. `isSubPixel` widens `subpixelSnap` by `max(|jitterPixels.x|, |jitterPixels.y|)` and `testTrianglePixel` uses jittered `SV_Position` (both exact). Three gaps remain: (1) `intersectFrustum` has no jitter margin, so boxes 0–0.5 px past an unjittered screen edge are culled even on jitter phases that shift them onto the border pixel; (2) late `isHiZOccluded` tests unjittered `viewProj` against the early Hi-Z built from *this frame's jittered depth*, so a silhouette occludee peeking <0.5 px under jitter can be falsely rejected in the final late phase; (3) while `isCameraFrozen`, `view.subpixelSnap` still adds the live cycling `jitterPixels`, slightly varying frozen sub-pixel culling per frame | [culling.slang:48-51](../shaders/core/culling.slang#L48-L51), [:181-192](../shaders/core/culling.slang#L181-L192), [meshlet_cull.slang:21-26](../shaders/passes/meshlet_cull.slang#L21-L26), [vk_meshlet_culling.cpp:386-387](../src/render/vk_meshlet_culling.cpp#L386-L387), [:413](../src/render/vk_meshlet_culling.cpp#L413), [:437-439](../src/render/vk_meshlet_culling.cpp#L437-L439) | Theoretical ≤0.5 px border flicker or silhouette pop under DLSS-RR jitter (16 Sponza poses passed with `ENGINE_JITTER=1`, so rare in practice; frozen sub-pixel counts wobble slightly) | Keep per §12.2 unless observed; if needed, pass jittered `viewProj` as late `occlusionViewProj` (exact match to early depth and late raster) or widen frustum/Hi-Z NDC rect by `abs(jitterOffset)`. Zero `jitterPixels` when `isCameraFrozen` |
| **C7** | **Sync precision** | **Minor barrier mask mismatches in `recordCounterReadback` and `HiZPyramid::recordBuild`.** (1) `recordCounterReadback` uses `srcStageMask = eComputeShader \| eMeshShaderEXT`, `srcAccessMask = eShaderStorageWrite`, omitting `eTransfer` / `eTransferWrite` from `cmd.updateBuffer` in `recordCull(Early)`. When the scene is empty (`templates.instances.empty()`), no compute/mesh shader writes `counters` before host readback. (2) `previousBuildBarrier` in `vk_hiz.cpp` pairs `srcStageMask = eComputeShader \| eFragmentShader` with `srcAccessMask = eShaderStorageWrite`, even though `hiz_view` only performs `eShaderSampledRead` in fragment (and `fragmentStoresAndAtomics` is not enabled) | [vk_meshlet_culling.cpp:458](../src/render/vk_meshlet_culling.cpp#L458), [:535-544](../src/render/vk_meshlet_culling.cpp#L535-L544), [vk_hiz.cpp:141-151](../src/render/vk_hiz.cpp#L141-L151) | Works on NVIDIA drivers and current VVL (host-coherent memory + fence covers empty scene; execution dependency covers fragment WAR), but imprecise under strict sync2 semantics | Add `eTransfer` / `eTransferWrite` to `recordCounterReadback`. In `vk_hiz.cpp`, split `previousBuildBarrier` into two barriers (`eComputeShader / eShaderStorageWrite → eComputeShader / eShaderStorageWrite` and execution-only `eFragmentShader / eNone → eComputeShader / eShaderStorageWrite`) and fix the stale comment on line 141 (`present` pass, not late raster) |
| **C8** | **Behavior** | **`isBoxOccluded` ignores `intersectFrustum`'s return value.** A box outside the *previous* frustum (entering from the side during a turn, all corners `w > 0` and `z <= w`) has its clip rect clamped to the screen border (`u = 0/1` or `v = 0/1`) while `bounds.isValid` remains `true`. `isHiZOccluded` then compares it against whatever depth happens to sit on that 1-texel border | [meshlet_cull.slang:21-26](../shaders/passes/meshlet_cull.slang#L21-L26), [culling.slang:103-105](../shaders/core/culling.slang#L103-L105) | Image is always conservative (two-phase recovers it), but whether newly-entering objects draw early or late depends arbitrarily on border depth and wastes a Hi-Z fetch per entering object. Also, if frustum culling is toggled off in the UI while occlusion stays on, offscreen boxes are miscounted as `Occluded` | Short-circuit in `isBoxOccluded`: `if (!intersectFrustum(...)) return false;` (treat outside-previous-frustum as untestable/visible early without a texture fetch) |

## 4. Performance Findings (Hypotheses)

Per the `vulkan-dev` skill §6.1, none of these should land without before/after Release GPU timer numbers with `vkconfig` and all validation layers off.

| ID | Finding | Location | Why it costs | Option |
|---|---|---|---|---|
| **P1** | **`cullMeshlets` loads per-meshlet structs and runs cone culling on already-culled groups.** (1) Line 254 checks `!isFrustumCulled` but omits `!isGroupSubPixel`, so every lane of a terminally sub-pixel-culled group still runs `worldToObject` + `isConeBackfacing` (and miscounts them as `coneCulled`). (2) Lines 242–243 load `GpuMeshletDesc` (32 B) and `GpuMeshletBounds` (32 B) unconditionally for every lane before checking `isGroupFrustumCulled \|\| isGroupSubPixel`. (3) `worldToObject(world, view.cameraPos)` is group-uniform yet sits inside the per-lane `if (isPresent)` branch | [meshlet_cull.slang:239-268](../shaders/passes/meshlet_cull.slang#L239-L268) | In Sponza, 142 of 182 groups cull whole; loading 64 B/lane, running `waveAppend` (zero bits), and running `groupRejectMask` shared-memory barriers/atomics on dead groups wastes bandwidth and ALU | Early-exit the workgroup when `isGroupFrustumCulled \|\| isGroupSubPixel`: lane 0 writes `rejectMasks[groupId.x] = 0` (early) and adds `meshletGroup.meshletCount` to the matching stat counter (when `kCullStats`), then returns. Hoist `worldToObject` out of `if (isPresent)` |
| **P2** | **Empty late phase and duplicate Hi-Z builds run when occlusion is disabled or history is invalid.** When `!settings.isOcclusionEnabled` or `history != OcclusionHistory::Valid`, early occlusion is skipped so zero candidates and zero reject bits exist. Yet the renderer still runs: `cullInstances(Late)` (0 groups), `cullMeshlets(Late)` (0 groups), `cullRejectedMeshlets` over **every early draw record** (all reading `rejectMask == 0` and returning), `buildMeshSequences(Late)`, `dgc.recordPreprocess(Late)`, depth/vis barriers, an empty late render pass, and a **full second 11-mip `LateHiZ` build** over unchanged depth | [vk_renderer.cpp:410-417](../src/render/vk_renderer.cpp#L410-L417), [:591-687](../src/render/vk_renderer.cpp#L591-L687), [vk_meshlet_culling.cpp:450-532](../src/render/vk_meshlet_culling.cpp#L450-L532) | Wastes compute dispatches, DGC preprocess, render-pass transitions, and 1–2 full Hi-Z builds whenever occlusion is off or on every fallback frame (camera cut / resize / load) | Skip the entire late phase (and `LateHiZ`) whenever early occlusion did not run; leave `EarlyHiZ` running when `isOcclusionEnabled \|\| debugView == HiZPyramid` (only transitioning depth when skipping `EarlyHiZ` too, and clearing `hiz.isBuilt` while skipped) |
| **P3** | **Early `isGroupOccluded` still projects every meshlet in the group to prune `rejectMasks`.** When the group box fails early Hi-Z, every lane still loads `GpuMeshletDesc` + `GpuMeshletBounds` and runs frustum + cone + sub-pixel to avoid setting bits for non-visible meshlets in `rejectMasks` | [meshlet_cull.slang:230-267](../shaders/passes/meshlet_cull.slang#L230-L267) | Intentional (`culling_comparison.md` A3) so `cullRejectedMeshlets` skips back-facing/offscreen meshlets. In heavily occluded dense scenes (Bistro), early-phase per-meshlet projection of occluded groups can cost more than letting `cullRejectedMeshlets` re-test the group box first (which rejects the whole group in 1 test!) | Measure both in dense occluded scenes: if `isGroupOccluded` skips per-meshlet work in early phase and writes `(meshletGroup.meshletCount == 32 ? ~0u : (1u << meshletGroup.meshletCount) - 1u)` to `rejectMasks`, `cullRejectedMeshlets` would need to run frustum/cone/sub-pixel only on groups that *recover* late |
| **P4** | **`cullInstances` launches 64 lanes per instance.** Lane 0 tests the instance while 63 lanes wait at `GroupMemoryBarrierWithGroupSync()`; culled instances waste 63/64 lanes, and small-primitive instances (1–4 draw records) leave ~60 lanes idle during the template copy | [meshlet_cull.slang:143-179](../shaders/passes/meshlet_cull.slang#L143-L179) | Scales with instance count (visible in the 16k bunny field). `shader_audit.md` P1 already cut late cull 7% by moving tests to lane 0 | If instance counts grow further (e.g. large Bistro foliage/prop counts), split into 1 thread per instance with wave-ballot compaction + a flat record-copy pass |
| **P5** | **DGC preprocess buffer sizes all 4 `(phase, bin)` regions for the full multi-phase capacity.** `allocatePreprocessBuffer` queries `queryPreprocessSize(capacity)` where `capacity >= 2 * phaseSequences` and allocates 4× that stride | [vk_dgc.cpp:204-231](../src/render/vk_dgc.cpp#L204-L231) | Minor VRAM overhead (~4×) when `sequenceCapacity` is large (small today with 1 sequence/bin, larger when testing small `maxMeshletsPerSequence` or with more bins) | Query per-bin max sequence capacity (or single-phase capacity) instead of combined multi-phase capacity |
| **P6** | **Absolute `kHiZDepthNudge` under reverse Z weakens far-distance occlusion.** `2.0 / 16777216.0` is ~2 ulps at `d = 1` (`nearPlane = 0.1 m`), but grows to ~0.6 m at `500 m` and ~21 m at `950 m` (`farPlane = 1000 m`) | [culling.slang:33](../shaders/core/culling.slang#L33), [:191](../shaders/core/culling.slang#L191), [vk_camera.hpp:105-106](../src/scene/vk_camera.hpp#L105-L106) | Conservative (never over-culls), slightly under-culls distant occludees behind distant occluders. Measured neutral on short Sponza views (`shader_audit.md` P8) | Re-evaluate a relative nudge (e.g. `farthest * (1.0 - eps)`) on long exterior views once Bistro loads |
| **P7** | **32-thread culling/mesh workgroups on future AMD wave64.** `kMeshletGroupMaxSize = 32` (`cullMeshlets`, `cullRejectedMeshlets`) and `kGroupSize = 32` (`meshMain`) are exact for NVIDIA warps (32) and AMD wave32, and remain *correct* on AMD wave64 (`Wave*` ops respect the active exec mask), but leave 50% of SIMD lanes idle if scheduled in wave64 | [types.slang:8-10](../shaders/types.slang#L8-L10), [meshlet_cull.slang:185](../shaders/passes/meshlet_cull.slang#L185), [:327](../shaders/passes/meshlet_cull.slang#L327), [mesh_raster.slang:24](../shaders/passes/mesh_raster.slang#L24) | No cost on RTX 20–50; relevant only when RX 9000+ becomes an active target | Keep as-is for NVIDIA; on AMD RDNA 4, either enforce wave32 (`VK_EXT_subgroup_size_control`) or pack two 32-meshlet groups per 64-thread workgroup |

| **8-corner frustum outcodes** | All 7 tests in `getCullBits` ([culling.slang:45-56](../shaders/core/culling.slang#L45-L56)) are linear homogeneous half-spaces, so `andBits != 0` is strictly conservative even when corners straddle `w <= 0`. `kClipNear = kClipZAbove` (`z > w`) and `kClipBehindEye` (`w <= 0`) mark near/eye-crossing boxes invalid while keeping far-plane-crossing boxes (`z < 0`, all `w > 0`) testable under reverse Z — fixing the standard-Z leftover in `vk_lod_clusters/shaders/culling.glsl:118` |
| **Hi-Z mip choice & 1-fetch coverage** | For any clamped `uvRect`, `hizMip` ([culling.slang:165-177](../shaders/core/culling.slang#L165-L177)) chooses a mip where the rect spans ≤ 1 texel, or `mip - 1` when `frac(x0) + (x1 - x0) <= 2.0` (`x1 <= floor(x0) + 2`). Whenever `k <= x0 < k+1 < x1 <= k+2`, the center `c = (x0 + x1) / 2` strictly satisfies `k + 0.5 < c < k + 1.5`, so Vulkan bilinear min-reduction (`i0 = floor(c - 0.5)`) always samples `{k, k+1}` — covering the full rect on both square and non-square pyramids |
