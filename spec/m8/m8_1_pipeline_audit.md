## 1. Objective

Audit the engine's current rendering pipeline line by line against NVIDIA's official reference implementations before building the M8.3 composable toggle system, M8.4 SHaRC integration, and M8.5 performance pass. Every verified correctness bug, synchronization hazard, reference deviation, and performance bottleneck is classified with exact `file:line` citations on both the engine side and the NVIDIA reference side.

No engine source files are modified during the audit phase; verified bugs and prioritized fixes are queued at the end of this document for execution before M8.2 / M8.3.

## 3. Classification Rules

- **`BUG` (P0 / P1):** Incorrect math, broken synchronization, missing barrier/wait, out-of-bounds/NaN risk, validation hazard, or mismatch with SDK contracts that produces wrong radiance, bias, missing geometry, or device loss.
- **`PERF` (P1 / P2):** Avoidable GPU/CPU cost relative to NVIDIA demos or modern Vulkan 1.4 best practices (extra passes, redundant rays, unnecessary reservoir pack/unpack, poor memory coalescing/register pressure, stalled async overlap).
- **`DEVIATION`:** Intentional or undocumented departure from NVIDIA's reference code; evaluated as *keep* (better for our architecture), *align* (adopt NVIDIA's behavior), or *make toggleable*.
- **`MATCH`:** Confirmed parity with the NVIDIA reference (recorded briefly so audited items are not re-audited later).

### 4.2 Domain B · RTX Mega Geometry, OMM & RT Scene (incl. `C-GA-1` / `C-T-6` / `C-I14-6`)

#### Root-Cause Analysis of `C-GA-1` / `C-T-6` / `C-I14-6` (Proven & Fixed in Wave 1)

1. **"16 frames" was a log cap, not recovery:** `EngineRayCheck::kMaxLoggedFailures = 16` (`src/checks/engine_ray_check.hpp:27`, `.cpp:54-56`) stops printing after 16 failures; all 25 framed frames of `MetalRoughSpheres_flat_normals_front` missed because the BLAS was permanently corrupted at load time.
2. **Exact root cause (verified via GPU readback & 4 MiB scratch-tail canary):** On `MetalRoughSpheres_flat_normals_front` (`24,281` clusters, `5` BLAS, `maxPerBlas = 5,946`), NVIDIA driver `621.01` reports `buildScratchSize = 1,880,576 B` (`0x1cb200`) for `eBuildClustersBottomLevel` / `eExplicitDestinations` (larger than `clasExplicit = 728,832 B`, leaving zero accidental headroom). During Submit 3 (`vkCmdBuildClusterAccelerationStructureIndirectNV` for `blasInput`), the driver writes **144 bytes (`36` dwords of `0xFFFFFFFF`) past `scratch.address + buildScratchSize`** (`firstOffset = 0 B, lastEnd = 144 B`).
3. **Why it corrupted `blas[0]` in `GuideCapture` and flipped on upload-order changes (`C-I14-6`):** Whenever VMA suballocated `model.blas` (in `GuideCapture`: `scratch = 0x1881d600 + 0x1cb200 == blas = 0x189e8800`) or `model.clas` (in standalone: `scratch = 0x11083f00 + 0x1cb200 == clas = 0x1124f100`) immediately after `scratch`, the 144-byte overrun smashed its first 64+ bytes with `0xFFFFFFFF` (causing 4,062/4,062 misses on every frame of `MetalRoughSpheres_flat_normals_front`, or `VK_ERROR_DEVICE_LOST` under validation). Scenes like Bistro had `rawScratchBytes = 14.7 MiB >> blasExplicit = 3.56 MiB`, accidentally hiding the bug.
4. **Fix (`BUG-B7`, plus `BUG-B1`–`BUG-B3` hardening):** Pad transient cluster-BLAS scratch in `MegaGeometry::buildModel` by `alignUp(max(64 KiB, blasScratchBytes / 16), scratchAlignment)` (zero persistent VRAM cost; freed when `buildModel` returns), stage build inputs into `DeviceLocal` memory (`BUG-B3`), and add the missing post-BLAS and PTLAS AS-read barriers (`BUG-B1`, `BUG-B2`). Re-verified `ENGINE_GUIDE_CAPTURE=1 ENGINE_RT_CHECK=1`: **8,890 of 8,890 frames matched** (`0` misses).
