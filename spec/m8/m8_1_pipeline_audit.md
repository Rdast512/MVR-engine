## 1. Objective

Audit the engine's current rendering pipeline line by line against NVIDIA's official reference implementations before building the M8.3 composable toggle system, M8.4 SHaRC integration, and M8.5 performance pass. Every verified correctness bug, synchronization hazard, reference deviation, and performance bottleneck is classified with exact `file:line` citations on both the engine side and the NVIDIA reference side.

No engine source files are modified during the audit phase; verified bugs and prioritized fixes are queued at the end of this document for execution before M8.2 / M8.3.

## 3. Classification Rules

- **`BUG` (P0 / P1):** Incorrect math, broken synchronization, missing barrier/wait, out-of-bounds/NaN risk, validation hazard, or mismatch with SDK contracts that produces wrong radiance, bias, missing geometry, or device loss.
- **`PERF` (P1 / P2):** Avoidable GPU/CPU cost relative to NVIDIA demos or modern Vulkan 1.4 best practices (extra passes, redundant rays, unnecessary reservoir pack/unpack, poor memory coalescing/register pressure, stalled async overlap).
- **`DEVIATION`:** Intentional or undocumented departure from NVIDIA's reference code; evaluated as *keep* (better for our architecture), *align* (adopt NVIDIA's behavior), or *make toggleable*.
- **`MATCH`:** Confirmed parity with the NVIDIA reference (recorded briefly so audited items are not re-audited later).

#### Deviations & Matches

- **Deviations:** `envBrdfApprox` (`brdf.slang:183-197`) uses separable Smith coefficients for a height-correlated Smith BRDF (switch to correlated fit from `Microfacet.hlsli:322-342`); no multi-scattering GGX energy compensation (`BxDF.hlsli:263-271`) or delta mirror lobe (`kMinAlpha = 1e-3`); fractional metallic (`0 < m < 1`) attenuates diffuse by `(1 - F(f0))` instead of `(1 - F(0.04))`; spot light presampling power (`light_world.slang:190`) ignores cone solid angle `0.5 * (1 - cos(outerCone))`; normal map Z is always reconstructed from XY.

### 4.2 Domain B · RTX Mega Geometry, OMM & RT Scene (incl. `C-GA-1` / `C-T-6` / `C-I14-6`)

#### Root-Cause Analysis of `C-GA-1` / `C-T-6` / `C-I14-6`

1. **"16 frames" is a log cap, not recovery:** `EngineRayCheck::kMaxLoggedFailures = 16` (`src/checks/engine_ray_check.hpp:27`, `.cpp:54-56`) stops printing after 16 failures. In `build/cafe-release/logs/gpuav_full/guide_rt_nolayers.engine.log:1414-1429, 2727`, **all 24 framed frames** (`shotFrame = 1..24`; 25 frames with 23 views) of `MetalRoughSpheres_flat_normals_front` failed — even though `Engine::mainLoop` calls `deviceRef.waitIdle()` after every frame under `rayCheck` (`vk_engine.cpp:539-542`). The RT structure is **permanently defective for the entire shot**.
2. **Only Primitive 0 (`Mesh 4 = "Spheres"`, holding the 4 label plaques = 4,062 interior px) misses, while `blas[1..4]` (sphere columns) hit:** `edgeMismatches = 123` (vs 151 passing) requires `isHit == true` (`rt_check.slang:350`), and `shotFrame == 0` (zoomed on center spheres before `frameShot`) passed with 0 misses.
3. **Why it latches permanently and flips on upload-order changes (`C-I14-6`):** `RayTracingScene::recordBuild` latches `ptlas.version = templates.version` on `shotFrame == 0` (`vk_rt_scene.cpp:739, 778`) and every subsequent frame runs an in-place update with `argCount == 0`. Two synchronization/memory hazards sit directly on the `AssetBuffers::flush` → `MegaGeometry::buildModel` → `RayTracingScene::recordBuild` path (`BUG-B1`, `BUG-B3`).
